### Requirement 18: Board Share Links

**User Story:** As a Board_Owner, Manager, or Admin, I want to share a read-only view of a Board through a link that I can revoke, so that people without an account can see the work without seeing the discussion.

#### Acceptance Criteria
**Round 3 within V10 (Decisions U to W):** criterion 11 reworded (assignee full name only; Open Question 13 resolved); 25 added (no avatar, Username, or Email in shared payloads).

New in V10 (Decision K). Criteria 1 to 23 are new in V10; criterion 24 is added in round 2 within V10 (Decision T).

1. [SHARE-01] THE Backend SHALL store a nullable, unique `share_token` on each Board, where null means sharing is off (Decision K).
2. [SHARE-02] WHEN the Board_Owner, a Manager, or an Admin calls `POST /api/boards/{id}/share` while sharing is off, THE Backend SHALL generate a Share_Token of at least 256 bits from a cryptographically secure source, store it, write one `board.share_enabled` Activity_Log row in the same transaction, and return `{ "enabled": true, "token": string, "path": "/shared/<token>" }` (Decision K).
3. [SHARE-03] WHEN the Board_Owner, a Manager, or an Admin calls `POST /api/boards/{id}/share` while sharing is on, THE Backend SHALL return the existing Share_Token unchanged and write no Activity_Log row.
4. [SHARE-04] WHEN the Board_Owner, a Manager, or an Admin calls `POST /api/boards/{id}/share/regenerate`, THE Backend SHALL replace the Share_Token with a new one, write one `board.share_regenerated` Activity_Log row, and make the previous Share_Link stop working at once (Decision K).
5. [SHARE-05] WHEN the Board_Owner, a Manager, or an Admin calls `DELETE /api/boards/{id}/share`, THE Backend SHALL set `share_token` to null, write one `board.share_disabled` Activity_Log row when sharing was on, and make the previous Share_Link stop working at once; WHEN sharing is already off, THE Backend SHALL return HTTP 200 and write no row (Decision K).
6. [SHARE-06] WHEN the Board_Owner, a Manager, or an Admin calls `GET /api/boards/{id}/share`, THE Backend SHALL return `{ "enabled": boolean, "token": string or null, "path": string or null }`.
7. [SHARE-07] IF any other signed-in user, including a Supervisor who is only a BoardMember, calls an endpoint of criteria 2 to 6, THEN THE Backend SHALL return HTTP 403, or HTTP 401 when no Token is present.
8. [SHARE-08] THE Backend SHALL keep the Share_Token out of every Activity_Log `metadata`, every log line, and every Board response other than the responses of criteria 2 to 6.
9. [SHARE-09] WHEN a visitor calls `GET /api/shared/{token}` with the Share_Token of a non-deleted Board, THE Backend SHALL return HTTP 200 without requiring a Token, with the Board's `id`, `name`, `description`, its Columns, and `has_board_access`, and without `owner_id`, members, `share_token`, `comments`, `activity`, or `activity_log` (Decision K).
10. [SHARE-10] IF a Share_Token is unknown, was disabled or replaced, or belongs to a soft-deleted Board, THEN every shared route SHALL return the same HTTP 404 `NOT_FOUND` response.
11. [SHARE-11] WHEN a visitor calls `GET /api/shared/{token}/cards`, THE Backend SHALL return the Cards of that Board that `GET /api/boards/{id}/cards` returns, each with its Subtasks, Attachments, and the assignee's `full_name` as `assignee_name` (plus the opaque `assignee_id` that the Card list already carries, but never the assignee's Username, Email, or Avatar_URL), and SHALL accept `search` and `filter[priority|assignee|category]` as Requirement 12 defines; the shared filter row of the Frontend offers search and Category chips only (Decision W, resolving Open Question 13).
12. [SHARE-12] WHEN a visitor calls `GET /api/shared/{token}/categories`, THE Backend SHALL return the Categories of that Board only.
13. [SHARE-13] WHEN a visitor calls `GET /api/shared/{token}/cards/{card_id}`, THE Backend SHALL return the Card with its Subtasks and Attachments, and SHALL return HTTP 404 when the Card does not belong to the Board of that Share_Token or is soft-deleted.
14. [SHARE-14] WHEN a visitor calls `GET /api/shared/{token}/attachments/{id}/url` for an Attachment of a Card of that Board, THE Backend SHALL return a Signed_File_URL scoped to that Share_Token, and SHALL return HTTP 404 for any other Attachment.
15. [SHARE-15] THE Backend SHALL expose no Comment endpoint, no Activity endpoint, and no mutating method under `/api/shared/`, so that a Guest never receives Comments or Activity_Log data through a Share_Link, whether the Board is public or private (Decision K).
16. [SHARE-16] WHEN a Signed_File_URL scoped to a Share_Token is presented to the file route, THE Backend SHALL return HTTP 403 unless the signature is valid, unexpired, and the Board's current Share_Token still matches the scope, so that disabling or regenerating a Share_Link invalidates outstanding file URLs at once.
17. [SHARE-17] WHERE a Board is `private`, THE Backend SHALL allow the Board_Owner, a Manager, or an Admin to enable a Share_Link, and SHALL keep returning HTTP 403 to a signed-in user without Board_Access on every non-shared route of that Board (Requirement 11, criterion 6).
18. [SHARE-18] THE Backend SHALL apply no expiry date to a Share_Token in V10.
19. [SHARE-19] THE Backend SHALL send `Cache-Control: private, no-store` on every shared route response, and THE Frontend SHALL send `Referrer-Policy: no-referrer` and `X-Robots-Tag: noindex` on every `/shared/{token}` page.
20. [SHARE-20] WHEN a signed-in user opens `/shared/{token}` and `has_board_access` is true, THE Frontend SHALL redirect to `/boards/{id}`; otherwise THE Frontend SHALL show the Shared_View (Decision K).
21. [SHARE-21] THE Frontend SHALL render the Shared_View without drag-and-drop, add-card, edit, assign, Comments, Activity, Inbox, Sidebar, or App_Header User_Menu, with a "Shared view, read only" banner and a Sign in link, SHALL open a Card as a read-only modal with no footer actions, and SHALL open Attachments through `target="_blank"` and `rel="noopener noreferrer"`, requesting a fresh URL from `GET /api/shared/{token}/attachments/{id}/url` when a Signed_File_URL has expired.
22. [SHARE-22] WHERE the viewer is the Board_Owner, a Manager, or an Admin, THE Frontend SHALL show a Share button in the Board's App_Header that opens a popover with the current state, an enable toggle, the full link with a Copy button, a Regenerate action, and a Disable action; Regenerate and Disable SHALL ask for confirmation through `BaseConfirm` and SHALL say that the old link stops working.
23. [SHARE-23] IF the shared route answers HTTP 404, THEN THE Frontend SHALL show a page that says the link is not valid and offers a Sign in link, without saying whether the link was disabled or never existed.

24. [SHARE-24] IF a request to a shared route carries a malformed, expired, or invalid Bearer Token, THEN THE Backend SHALL ignore the Token and answer as for a request with no Token (never 401), with `has_board_access` false, so that a stale Session_Cookie cannot break a Share_Link (Decision T).
25. [SHARE-25] THE Backend SHALL carry in no shared route response any `avatar_url`, `author_avatar_url`, `assignee_avatar_url`, Username, or Email of a user, so that the Shared_View shows an assignee by `assignee_name` and an Initials_Avatar only (Decision U, Decision W).
