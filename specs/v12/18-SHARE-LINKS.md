# Public links (formerly share links), V12 changes

Requirement 23 is new. The column `share_token`, the routes, and the page `/shared/{token}` keep their names.

### Requirement 23: Public Link

**User Story:** As a Manager or Admin, I want to publish a read-only view of a Board through a link that I can revoke, so that anyone holding the link can see the work without gaining access to the discussion or to any edit action.

Note (V12, Decision Z): the V10 Share_Link is renamed Public_Link. The stored column stays `Board.share_token`, the Share_Token keeps its name in code, and the routes stay `/api/boards/{id}/share...`, `/api/shared/{token}...`, and the page `/shared/{token}`, so that no URL, column, or Frontend route changes; only the roles and the wording change. Requirement 18 criteria 2 to 7, 17, 21, and 22 are amended below; the other criteria of Requirement 18 stand.

#### Acceptance Criteria

1. [PUB-01] WHEN a Manager or an Admin calls `POST /api/boards/{id}/share`, `POST /api/boards/{id}/share/regenerate`, `DELETE /api/boards/{id}/share`, or `GET /api/boards/{id}/share`, THE Backend SHALL apply the behaviour of Requirement 18, criteria 2 to 6, to the Board (Decision Z; amends Requirement 18, criteria 2 to 6).
2. [PUB-02] IF a signed-in user who is not a Manager or an Admin, the Board_Owner and a Supervisor BoardMember included, calls an endpoint of criterion 1, THEN THE Backend SHALL return HTTP 403, or HTTP 401 when no Token is present (Decision Z; amends Requirement 18, criterion 7).
3. [PUB-03] WHEN any visitor, a Guest or a signed-in user with or without Board_Access, opens a Public_Link whose Share_Token is current, THE Backend SHALL answer the shared routes of Requirement 18, criteria 9 to 14, with HTTP 200 and read-only data, and SHALL return `has_board_access` true only when the signed-in caller has Board_Access (Decision Z).
4. [PUB-04] WHEN a signed-in user with Board_Access opens `/shared/{token}`, THE Frontend SHALL redirect to `/boards/{id}`; WHEN any other visitor opens it, THE Frontend SHALL show the Shared_View, a signed-in user without Board_Access included (Decision Z; Requirement 18, criterion 20).
5. [PUB-05] THE Backend SHALL NOT return Comments, the Activity_Log, `owner_id`, the member list, `invite_token`, `share_token`, any Email, Username, or Avatar_URL from any route under `/api/shared`, whoever calls it (Requirement 18, criteria 9, 15, and 25).
6. [PUB-06] WHEN a Manager or an Admin regenerates or disables the Public_Link, THE Backend SHALL make the previous link and every Signed_File_URL issued through it stop working at once, and THE Backend SHALL apply no expiry date to a Share_Token (Requirement 18, criteria 4, 5, 16, and 18).
7. [PUB-07] THE Frontend SHALL render in the Shared_View and for any visitor without Board_Access no write control: no add-card, no drag handle, no edit field, no chip popover trigger, no Subtask checkbox that can be toggled, no attachment add or remove control, no comment composer, no Archive, no Delete, no Invite button, no Public link button, and no assignee control (Decision Z; Requirement 18, criterion 21).
8. [PUB-08] WHERE the viewer of the Shared_View is signed in without Board_Access, THE Frontend SHALL show a "Go to Home" link in the banner in place of the Sign in link (Decision Z).
9. [PUB-09] WHERE the viewer is a Manager or an Admin on a Board, THE Frontend SHALL show a "Public link" button in the Board's App_Header that opens the popover of Requirement 18, criterion 22, and SHALL show no such button to the Board_Owner or any other viewer (Decision Z; amends Requirement 18, criterion 22).
10. [PUB-10] IF an unauthenticated visitor calls `POST /api/cards/{id}/comments`, `PATCH /api/cards/{id}`, `POST /api/cards/{id}/attachments`, `PATCH /api/subtasks/{id}`, `POST /api/cards/{id}/archive`, or `DELETE /api/cards/{id}`, THEN THE Backend SHALL return HTTP 401 and change nothing.
11. [PUB-11] IF a signed-in user without Board_Access calls any endpoint of criterion 10 for a Card of a Board whose Public_Link they hold, THEN THE Backend SHALL return HTTP 403 and change nothing, because a Share_Token grants no write access on any route outside `/api/shared`.
12. [PUB-12] THE Backend SHALL answer any POST, PATCH, PUT, or DELETE under `/api/shared` with HTTP 405 and change nothing (Requirement 18, criterion 15).

### Requirement 18 criteria with V12 labels

Criteria of Requirement 18 that V12 changed. Each line is the full V1 to V11 criterion followed by its V12 label; the label wins.

2. [SHARE-02] WHEN the Board_Owner, a Manager, or an Admin calls `POST /api/boards/{id}/share` while sharing is off, THE Backend SHALL generate a Share_Token of at least 256 bits from a cryptographically secure source, store it, write one `board.share_enabled` Activity_Log row in the same transaction, and return `{ "enabled": true, "token": string, "path": "/shared/<token>" }` (Decision K). **(Amended in V12 by Requirement 23, criterion 1: Manager and Admin only.)**
3. [SHARE-03] WHEN the Board_Owner, a Manager, or an Admin calls `POST /api/boards/{id}/share` while sharing is on, THE Backend SHALL return the existing Share_Token unchanged and write no Activity_Log row. **(Amended in V12 by Requirement 23, criterion 1: Manager and Admin only.)**
4. [SHARE-04] WHEN the Board_Owner, a Manager, or an Admin calls `POST /api/boards/{id}/share/regenerate`, THE Backend SHALL replace the Share_Token with a new one, write one `board.share_regenerated` Activity_Log row, and make the previous Share_Link stop working at once (Decision K). **(Amended in V12 by Requirement 23, criterion 1: Manager and Admin only.)**
5. [SHARE-05] WHEN the Board_Owner, a Manager, or an Admin calls `DELETE /api/boards/{id}/share`, THE Backend SHALL set `share_token` to null, write one `board.share_disabled` Activity_Log row when sharing was on, and make the previous Share_Link stop working at once; WHEN sharing is already off, THE Backend SHALL return HTTP 200 and write no row (Decision K). **(Amended in V12 by Requirement 23, criterion 1: Manager and Admin only.)**
6. [SHARE-06] WHEN the Board_Owner, a Manager, or an Admin calls `GET /api/boards/{id}/share`, THE Backend SHALL return `{ "enabled": boolean, "token": string or null, "path": string or null }`. **(Amended in V12 by Requirement 23, criterion 1: Manager and Admin only.)**
7. [SHARE-07] IF any other signed-in user, including a Supervisor who is only a BoardMember, calls an endpoint of criteria 2 to 6, THEN THE Backend SHALL return HTTP 403, or HTTP 401 when no Token is present. **(Amended in V12 by Requirement 23, criterion 2: the Board_Owner gets 403.)**
15. [SHARE-15] THE Backend SHALL expose no Comment endpoint, no Activity endpoint, and no mutating method under `/api/shared/`, so that a Guest never receives Comments or Activity_Log data through a Share_Link, whether the Board is public or private (Decision K). (V12: every Board is private; the rule holds for all.)
17. [SHARE-17] WHERE a Board is `private`, THE Backend SHALL allow the Board_Owner, a Manager, or an Admin to enable a Share_Link, and SHALL keep returning HTTP 403 to a signed-in user without Board_Access on every non-shared route of that Board (Requirement 11, criterion 6). **(Obsolete in V12: no Board is public; a Manager or an Admin may enable a Public_Link on any Board.)**
21. [SHARE-21] THE Frontend SHALL render the Shared_View without drag-and-drop, add-card, edit, assign, Comments, Activity, Inbox, Sidebar, or App_Header User_Menu, with a "Shared view, read only" banner and a Sign in link, SHALL open a Card as a read-only modal with no footer actions, and SHALL open Attachments through `target="_blank"` and `rel="noopener noreferrer"`, requesting a fresh URL from `GET /api/shared/{token}/attachments/{id}/url` when a Signed_File_URL has expired. (V12: no write control for any visitor, Requirement 23, criterion 7.)
22. [SHARE-22] WHERE the viewer is the Board_Owner, a Manager, or an Admin, THE Frontend SHALL show a Share button in the Board's App_Header that opens a popover with the current state, an enable toggle, the full link with a Copy button, a Regenerate action, and a Disable action; Regenerate and Disable SHALL ask for confirmation through `BaseConfirm` and SHALL say that the old link stops working. **(Amended in V12 by Requirement 23, criterion 9: the button is "Public link" and is shown to a Manager and an Admin only.)**
